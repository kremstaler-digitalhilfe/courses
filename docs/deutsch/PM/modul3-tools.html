Modul 3: Tools

Dokumentation und Zusammenarbeit

Nach diesem Modul kannst du …

  • erklären, wofür Teams digitale Tools (wie Jira, Confluence oder Trello) nutzen
  • Aufgaben, Wissen und Kommunikation dem richtigen Tool zuordnen
  • den Aufbau von Confluence beschreiben
  • ein Jira-Ticket und eine Confluence-Seite sinnvoll strukturieren
  • ein passendes Tool nach einfachen Kriterien auswählen

3.1 Warum Teams Tools brauchen

Ein Whiteboard im Raum reicht nicht mehr aus, wenn ein Team wächst oder im Homeoffice arbeitet. Digitale Tools machen Informationen für alle sichtbar und auffindbar.

Beispiel Banking-App:

Infos stecken verstreut …

📧 E-Mails🧠 Köpfe einzelner Personen📧 E-Mails🧠 „Frag Sarah!“
  • ? Wo steht, wie die Überweisung funktioniert?
  • ? Wer entscheidet, was als Nächstes gebaut wird?

  • Alle im Team können Informationen sehen und finden.
Wichtig: Ein Tool ersetzt keine Methode! Ein schlechtes Backlog wird auch durch ein teures Software-Tool nicht besser.

Confluence

3.3 Das gemeinsame Wissensarchiv

1Ein Wiki

von der Firma Atlassian

  • Eine Sammlung von Seiten, die alle im Team lesen und bearbeiten können.
  • Ähnlich einer gemeinsamen Online-Mappe.

2Spaces

Bereiche

  • Die Seiten liegen in Spaces.
  • Meist ein Space pro Team oder Projekt.

Was gehört hinein?

Projektsteckbrief

  • Ziel (SMART formuliert), Beteiligte, Zeitrahmen.

Anforderungen

  • Ausführliche Beschreibung einer User Story, z. B. der genaue Ablauf beim Zurücksetzen eines Passworts.

Definition of Done

  • Die gemeinsame Checkliste, wann etwas als fertig gilt.

Protokolle

  • Ergebnisse von Sprint Review und Retrospektive.

Entscheidungen

  • Was wurde warum entschieden, und von wem?

Anleitungen

  • Z. B. wie man die Testumgebung benutzt.

3.3 Tipps für Confluence

1Einheitliche Quelle

Single Source of Truth

  • Infos stehen nur an einer Stelle – keine Dopplungen.
✗ Dieselbe Info in 3 Seiten
→ widersprüchlich, veraltet
✓ Eine Seite
→ alle verlinken darauf

2Klarer Kopf

Jede Seite braucht …

  • einen eindeutigen Titel
  • ein Datum
  • eine verantwortliche Person
Banking-App-Team › Anforderungen

Passwort zurücksetzen

📅 Datum: TT.MM.JJJJ👤 Verantwortlich: Name

3Saubere Ordner

Zum Beispiel:

Hauptseite→ Anforderungen→ Passwort zurücksetzen
Merke dir:
  • Confluence = Wiki für Wissen, Regeln und Entscheidungen
  • Space = Bereich für ein Team oder Projekt
  • Eine Info = ein Ort, mit klarem Titel, Datum und Verantwortlichen

Das passende Tool

3.5 Wie wählt man ein Tool aus?

Die 3 goldenen Regeln

🌱Lieber klein anfangen

  • Ein einfaches Board, das alle nutzen, ist besser als ein überladenes Riesen-Tool.

🔗Bestehende Tools nutzen

  • Nutzt die Firma schon Microsoft oder Atlassian? Dann bleib im selben System.

🔒Daten schützen

  • Kläre vorab, wo die Daten gespeichert werden (Datenschutz).

Auswahl-Check

Bei der Auswahl zählen:

Teamgröße Kosten Bestehende Tools Einarbeitung Integrationen Datenschutz

Typische Fehler

🕸️Veraltet

  • Seiten und Tickets sind veraltet, und niemand traut ihnen mehr.

📝Zu viel Pflicht

  • Zu viele Pflichtfelder und Status – die Pflege nervt.

🧩Wildwuchs

  • Jede Person nutzt ein anderes Tool, Infos stehen nur im Chat.
Faustregel: Ein einfaches Tool, das alle wirklich pflegen, schlägt ein perfektes Tool, das niemand nutzt.

Zusammenfassung & Glossar

Modul 3

Zusammenfassung Modul 3

  • Tools machen Arbeit sichtbar, ersetzen aber keine agilen Methoden.
  • Jedes Tool hat einen Zweck:
    • Jira/Trello: Tickets (Epic, Story, Task, Bug) in Backlog, Board und Sprint
    • Confluence/Notion: Wissen
    • Slack oder Teams: schnelle Fragen
    • Miro: gemeinsames Skizzieren / digitale Workshops
  • Verlinke Jira und Confluence, um Aufgaben direkt mit Wissen zu verknüpfen.
  • Bei der Auswahl zählen Teamgröße, Kosten, bestehende Tools, Einarbeitung, Integrationen und Datenschutz. Lieber klein anfangen.

Glossar Modul 3

Bug: Fehler in einer Software.
Confluence / Notion: Wiki-Tool zum gemeinsamen Dokumentieren.
Epic: Große Anforderung, die in mehrere User Stories zerlegt wird.
Git: System zum Speichern und Verwalten von Programmcode.
Integration: Die Verknüpfung von zwei Tools (z. B. Jira und Confluence).
Jira/Trello: Tool zur Verwaltung von Tickets, Backlogs und Boards.
Miro: Digitales Whiteboard für Online-Workshops.
Space: Ein Ordnerbereich in Confluence für ein bestimmtes Projekt.
Task: Eine rein technische Aufgabe ohne direkten Kundennutzen.
Ticket (Issue): Ein digitaler Zettel für eine Aufgabe oder einen Fehler im Tool.
Versionshistorie: Liste früherer Fassungen einer Seite.
Wiki: Sammlung von Seiten, die ein Team gemeinsam bearbeitet.
Workflow: Abfolge der Status eines Tickets, z. B. To-Do, In Progress, Review, Done.
