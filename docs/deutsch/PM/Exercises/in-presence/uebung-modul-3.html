5 · Single Source of Truth

Was bedeutet das Prinzip?

  • A) Jedes Teammitglied speichert eine eigene Kopie aller Dokumente.
  • B) Eine Information steht genau an einem zentralen Ort, um Widersprüche zu vermeiden.
  • C) Dokumente dürfen nur von der Geschäftsleitung bearbeitet werden.

6 · Wozu dient ein Spike?

Im agilen Projekt …

  • A) Zum schnellen Beheben kritischer Fehler im Live-System.
  • B) Für eine zeitlich begrenzte Recherche, um eine offene Frage vorab zu klären.
  • C) Zum automatischen Erstellen von Testberichten in Confluence.

7 · Warum „vertikal“ schneiden?

User Stories …

  • A) Damit jede Story ein funktionierendes, testbares Stück Arbeit für den Nutzer liefert.
  • B) Weil Datenbanken immer vor der Benutzeroberfläche gebaut werden müssen.
  • C) Damit Entwickler und Designer völlig getrennt voneinander arbeiten können.

8 · Faustregel bei der Tool-Auswahl

Die wichtigste Regel …

  • A) Immer das teuerste Tool mit den meisten Funktionen wählen.
  • B) Für jede Aufgabe ein eigenes, spezialisiertes Tool anschaffen.
  • C) Lieber klein und einfach anfangen, damit das Board von allen gepflegt wird.
Merke dir:
  • Tools machen sichtbar – ersetzen keine Methode
  • Jira = Aufgaben · Confluence = Wissen
  • Eine Info = ein Ort · Spike = kurze Recherche
  • Vertikal schneiden · lieber einfach starten

Glossar

Jira: Tool für Tickets, Backlog und Boards.
Confluence: Wiki für gemeinsames Wissen und Doku.
Task: Technische Aufgabe ohne direkten Kundennutzen.
Single Source of Truth: Eine Information an genau einem Ort.
Spike: Zeitlich begrenzte Recherche zu einer offenen Frage.
Vertikal schneiden: Stories liefern nutzbaren Nutzen, nicht nur Technik-Schichten.
