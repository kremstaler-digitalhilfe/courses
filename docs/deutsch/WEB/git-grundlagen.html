Was ist Git?

1Git am Computer

Dein Speicherstand-System

  • Wie Speicherstände in einem Videospiel
  • Läuft lokal auf deinem Computer
  • Merkt sich jede Änderung, damit du zurückspulen kannst

2GitHub und GitLab

Die Cloud dafür

  • Wie Google Drive oder Dropbox
  • Hier lädst du Speicherstände hoch
  • Zum Sichern und zum Teilen im Team
Merke dir: Git ist das Werkzeug an deinem Computer. GitHub und GitLab sind die Websites, auf denen das Projekt liegt.

Installation

1Windows

Installer von der Website

  • Öffne git-scm.com (öffnet in neuem Tab)
  • Lade den Windows-Installer herunter
  • Klicke immer auf Next. Die Standardeinstellungen passen
  • Prüfen in PowerShell: git --version

2macOS

Zwei Wege

  • Mit Homebrew: brew install git
  • Ohne Extra-Software: git --version im Terminal
  • macOS fragt nach den Xcode Command Line Tools. Klicke auf Installieren
  • Prüfe danach noch einmal mit git --version
Tipp: Steht eine Versionsnummer da, ist Git installiert.
Seite 1 / 7

Die 3 Zustände

Jede Datei liegt in einem von drei Orten.

Working Directory→ Staging→ Repository

1Arbeitsverzeichnis

Working Directory

  • Deine aktuellen Dateien
  • Noch nicht gespeichert

2Staging

Auch Index genannt

  • git add legt Änderungen bereit
  • Für den nächsten Commit

3Repository

Der Ordner .git

  • Die dauerhafte Historie
  • Entsteht mit git commit

Wichtige Wörter

Branch

Ein Zweig

  • Ein paralleler Entwicklungsstrang
  • Der Hauptzweig heißt meist main
  • Früher hieß er master

Commit

Ein Schnappschuss

  • Der Stand des Codes zu einem Zeitpunkt
  • Jede Aufnahme hat eine Kennung, den Hash

HEAD

Der Zeiger

  • Zeigt immer auf den aktiven Commit
  • Oder auf den aktiven Branch

.gitignore

Die Ignorier-Liste

  • Eine Textdatei im Hauptordner
  • Git übersieht die genannten Dateien
  • Typisch: node_modules/ und .env
  • Auch Passwörter gehören hierher

Projekt starten

1Neu anlegen

git init

  • Macht aus dem Ordner ein lokales Repository
  • Legt den versteckten Ordner .git an

2Herunterladen

git clone

  • Holt ein bestehendes Remote-Projekt
  • Die Adresse steht in spitzen Klammern als Platzhalter
git init
git clone <repository-url>

Im Alltag

Schauen, vormerken, speichern, nachsehen.

git status

Wo stehe ich?

  • Zeigt geänderte und vorgemerkte Dateien

git diff

Was ist anders?

  • Zeigt die Änderung Zeile für Zeile

git log

Der Verlauf

  • Die Commits von neu nach alt

Commit anpassen

git commit --amend

  • Ändert den letzten Commit nachträglich
git status
git diff
git add .
git commit -m "Aussagekräftige Nachricht"
git log

# letzten Commit nachträglich anpassen
git add .
git commit --amend
Tipp: --amend nur nutzen, wenn der Commit noch nicht geteilt wurde.
Seite 3 / 7

Branches verwalten

Der aktive Branch ist in der Liste markiert.

git branch
git branch neues-feature
git switch neues-feature
# oder klassisch:
git checkout neues-feature
# anlegen und direkt wechseln:
git checkout -b neues-feature
Tipp: git switch wechselt den Branch. checkout -b legt ihn an und wechselt sofort.

Rückgängig machen

1Datei verwerfen

Noch nicht gespeichert

  • git restore index.html
  • Klassisch: git checkout -- index.html

2Aus dem Staging

Unstage

  • git restore --staged index.html
  • Die Datei bleibt geändert, ist nur nicht mehr vorgemerkt

3Revert

Sicher rückgängig

  • git revert <commit-hash>
  • Legt einen neuen Gegen-Commit an

4Reset

Vorsicht

  • git reset --hard <commit-hash>
  • Springt zurück und löscht spätere Commits
Goldene Regel: git revert ist der sichere Weg. git reset --hard löscht Nachfolgendes. Nur nutzen, wenn du dir sicher bist.
Seite 4 / 7

Beiseitelegen und aufräumen

Stash

Kurz weglegen

  • git stash versteckt halbfertige Änderungen
  • git stash pop holt sie zurück

Cherry-Pick

Einen Commit holen

  • Nimmt einen Commit von einem anderen Branch
  • git cherry-pick <commit-hash>

Squash

Commits bündeln

  • git rebase -i HEAD~3
  • Öffnet den Editor für die letzten 3 Commits
git stash
git stash pop
git cherry-pick <commit-hash>
git rebase -i HEAD~3

Remote-Repositories

git push

Hochladen

  • Sendet lokale Commits an den Server, zum Beispiel GitHub oder GitLab

git fetch

Nur nachsehen

  • Lädt Infos über neue Änderungen. Dein lokaler Code bleibt gleich

git pull

Holen und einbauen

  • Das ist git fetch plus git merge

Origin

Dein Standard-Remote

  • Oft dein eigener Fork, also deine Kopie

Upstream

Das Original

  • Das Hauptprojekt, von dem du geforkt hast
Seite 5 / 7

Zusammenführen

Merge

git merge <branch-name>

  • Führt zwei Branches zusammen
  • Erzeugt einen neuen Merge-Commit
  • Beide Historien bleiben erhalten

Rebase

git rebase <branch-name>

  • Setzt deine Commits auf den neuesten Stand des Ziel-Branch
  • Die Historie wird linear
  • Dafür wird die Historie umgeschrieben
Goldene Regel: git push --force niemals auf main verwenden.

Konflikte lösen

Kann Git zwei Änderungen nicht allein zusammenführen, setzt es Marker in die Datei.

<<<<<<< HEAD
Dein lokaler Code
=======
Der fremde Code
>>>>>>> branch-name
Merke dir: So schließt du einen Konflikt
  • Den richtigen Code behalten
  • Die Marker <<< === >>> löschen
  • Datei speichern, dann git add und git commit
Seite 6 / 7

Im Team

Der übliche Weg ist der Feature-Branch-Workflow. Jedes neue Feature oder jeder Bugfix bekommt einen eigenen Branch. Fertig? Dann nach main zusammenführen.

Vorteil

Klare Trennung

  • Änderungen bleiben isoliert
  • Weniger Konflikte

Nachteil

Braucht Ordnung

  • Branches müssen diszipliniert gepflegt werden
Tipp: Je nach Team gibt es auch Gitflow, den Forking-Workflow, Pull Requests, Merge Requests oder Trunk-Based Development.

Zusammenfassung

Git lokal · GitHub in der Cloud add → commit → push Ein Branch pro Feature revert sicher · reset --hard vorsichtig
Merke dir:
  • Zuerst visuell lernen, dann die Befehle
  • Kleine Commits mit klarer Nachricht
  • Passwörter und .env gehören in die .gitignore
  • Kein push --force auf main

Glossar

Git: Werkzeug am Computer. Speichert jeden Stand.
GitHub / GitLab: Websites, auf denen das Projekt liegt.
Commit: Schnappschuss mit einer eindeutigen Kennung.
Staging: Änderungen, die für den nächsten Commit bereitliegen.
Branch: Ein paralleler Strang. Der Hauptstrang heißt meist main.
HEAD: Zeiger auf den aktiven Commit oder Branch.
Remote: Die Kopie auf dem Server. Origin ist deine, Upstream das Original.
Merge: Zwei Stränge zusammenführen. Beide Historien bleiben.
