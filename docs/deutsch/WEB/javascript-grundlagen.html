1. Variablen

Der Speicher des Computers

Programme müssen sich Werte merken können (z. B. den Punktestand in einem Spiel oder den Namen eines eingeloggten Nutzers). Dafür nutzen wir Variablen.

Wie man eine Variable erstellt: mit let oder const

1const

Constant = Konstante

  • Der Wert darf sich nicht mehr ändern, nachdem er einmal festgelegt wurde.

2let

Lass uns das ändern können

  • Der Wert darf sich im Laufe des Programms ändern (z. B. ein Punktestand, der steigt).
const name = "Anna";     // bleibt immer "Anna"
let punkte = 0;          // Startwert
punkte = punkte + 10;      // jetzt: 10

↑ name bleibt fest, punkte darf wachsen.

Datentypen

Jeder Wert hat einen Typ

Jeder Wert in JavaScript hat einen bestimmten Typ. Die wichtigsten drei:

1String

Text

  • Steht immer in Anführungszeichen.
  • "Hallo Welt"
  • 'JavaScript'

2Number

Zahl

  • Ganze Zahlen oder Kommazahlen.
  • 42
  • 3.14

3Boolean

Wahrheitswert

  • Nur zwei Zustände:
  • true (wahr)
  • false (falsch)
const text = "Hallo Welt";     // String
const alter = 42;              // Number
const pi = 3.14;               // Number (Kommazahl)
const istAngemeldet = true;   // Boolean
Wichtig: Zahlen schreibt man ohne Anführungszeichen – sonst hält JavaScript sie für Text!

✓ Richtig

  • const alter = 42; → Number

✗ Falsch

  • const alter = "42"; → String (Text!)
Boolean im Einsatz: Wird oft für Schalter oder Prüfungen genutzt – z. B. „ist der Nutzer angemeldet?“

Bedingungen

2. if / else – Entscheidungen im Code

Programme müssen oft Entscheidungen treffen: Ist der Nutzer volljährig? Wenn ja, zeige den Inhalt. Wenn nein, zeige eine Fehlermeldung. Dafür nutzt man Bedingungen.

const punkte = 75;

if (punkte >= 90) {
  console.log("Sehr gut!");
} else if (punkte >= 50) {
  console.log("Bestanden");
} else {
  console.log("Leider nicht bestanden");
}

↑ Bei 75 Punkten erscheint „Bestanden“.

Erklärung

1if (…)

  • Prüft, ob die Bedingung in den Klammern true ist. Wenn ja, wird der Code im ersten Block ausgeführt.

2else if

  • Fängt weitere Bedingungen ab.

3else

  • Greift, wenn keine der vorherigen Bedingungen gestimmt hat.
Vergleiche: >= größer oder gleich · <= kleiner oder gleich · === genau gleich (Wert und Typ)

Funktionen

3. Wiederverwendbare Code-Blöcke

Eine Funktion ist wie ein kleines Werkzeug oder ein Rezept. Du schreibst den Code einmal auf und kannst ihn beliebig oft aufrufen – ohne ihn neu zu schreiben.

A) Die Funktion definieren

Das Rezept schreiben

function begruesseNutzer(name) {
  console.log("Hallo " + name + "!");
}

function

  • Das Schlüsselwort: „Hier kommt eine Funktion.“

begruesseNutzer

  • Der selbst gewählte Name der Funktion.

(name)

  • Ein Parameter: Platzhalter für Daten, die wir von außen übergeben.

B) Die Funktion aufrufen

Das Rezept ausführen

Eine Funktion tut von alleine gar nichts. Du musst sie mit ihrem Namen aktivieren:

begruesseNutzer("Anna");   // Hallo Anna!
begruesseNutzer("Ben");    // Hallo Ben!

C) Der Rückgabewert (return)

Funktionen können nicht nur etwas auf der Konsole ausgeben, sondern auch ein Ergebnis zurückgeben, mit dem man weiterrechnen kann.

function addiere(a, b) {
  return a + b;
}

const summe = addiere(2, 3);   // summe ist 5
console.log(summe * 10);        // 50

Schleifen

4. for-Schleife – Wiederholungen automatisieren

Wenn du denselben Befehl 100-mal ausführen möchtest (z. B. alle Elemente einer langen Liste durchgehen), schreibst du das nicht 100-mal von Hand. Dafür gibt es Schleifen. Die for-Schleife ist der Klassiker, wenn man genau weiß, wie oft etwas wiederholt werden soll.

for (let i = 1; i <= 3; i++) {
  console.log("Durchlauf Nummer: " + i);
}

Was passiert in den Klammern?

(let i = 1; i <= 3; i++)

1Start

let i = 1;

  • Eine Zählvariable i (Index) – wir fangen bei 1 an.

2Bedingung

i <= 3;

  • Vor jedem Durchlauf: Ist i kleiner oder gleich 3? Solange true, läuft die Schleife. Bei 4 stoppt sie.

3Schrittweite

i++

  • Nach jedem Durchlauf wird i um 1 erhöht (++ = plus 1).
i = 1→ i <= 3 ?→ ja → Code ausführen→ i++↺

Bei „nein“ (i ist 4) endet die Schleife.

Ausgabe in der Konsole:

Durchlauf Nummer: 1
Durchlauf Nummer: 2
Durchlauf Nummer: 3

Arrays & Objekte

5. Daten speichern und sortieren

In echten Programmen hat man selten nur eine einzelne Variable, sondern Sammlungen von Daten.

1Arrays (Listen)

Eckige Klammern [ ]

  • Speichern mehrere Werte in einer geordneten Liste.
  • Jedes Element hat einen Platz (Index), der bei 0 beginnt.
const fruechte = ["Apfel", "Birne", "Kirsche"];

console.log(fruechte[0]);   // "Apfel"
console.log(fruechte[2]);   // "Kirsche"
"Apfel"Index 0
"Birne"Index 1
"Kirsche"Index 2

2Objekte (Strukturen)

Geschweifte Klammern { }

  • Speichern zusammengehörige Eigenschaften.
  • Als Schlüssel-Wert-Paare.
const nutzer = {
  name: "Anna",
  alter: 25,
  istAngemeldet: true
};

console.log(nutzer.name);   // "Anna"
Merke dir:
  • Array = Liste in [ ], Zugriff über die Nummer (Index ab 0)
  • Objekt = Eigenschaften in { }, Zugriff über den Namen

DOM & Events

6. Interaktion mit der Website

Das DOM (Document Object Model) ist die Brücke zwischen JavaScript und dem HTML. JavaScript kann das HTML lesen, verändern oder neue Elemente hinzufügen.

Elemente greifen und verändern

const titel = document.querySelector("h1");   // Element greifen

titel.textContent = "Neuer Titel";          // Text ändern
titel.style.color = "blue";                // Farbe ändern

1Greifen

  • querySelector("h1") findet ein Element über seinen CSS-Selektor.

2Verändern

  • textContent und style ändern Text und Aussehen.

Events: auf den Nutzer reagieren

JavaScript wartet passiv darauf, dass der Nutzer eine Aktion ausführt (Klick, Tastendruck, Scrollen). Dafür nutzt man addEventListener:

const knopf = document.querySelector("button");

knopf.addEventListener("click", function () {
  titel.textContent = "Du hast geklickt!";
});

Wer?

  • knopf – das Element, das lauscht

Was?

  • "click" – das Ereignis

Dann?

  • Die Funktion, die dann läuft

JS & Barrierefreiheit

7. A11y – keine unabsichtlichen Barrieren

Weil JavaScript Inhalte dynamisch verändern kann, entstehen hier oft unabsichtlich Barrieren für Screenreader-Nutzer:

1Fokus-Management bei Popups

  • Öffnet sich per JavaScript ein Menü oder Dialogfenster, muss der Fokus sofort in dieses Fenster wandern.
  • Schließt es sich wieder, muss der Fokus zum auslösenden Element zurückkehren.

2Änderungen ankündigen

aria-live

  • Ändert JavaScript Text (z. B. eine Fehlermeldung im Formular), bekommen blinde Menschen das nicht mit.
  • Mit aria-live="polite" sagt man dem Browser: Lies diese Änderung vor.

3Keine reine Maus-Abhängigkeit

  • Event-Listener niemals nur an einen Klick (click) knüpfen.
  • Jede Aktion muss auch per Tastatur auslösbar sein (Enter-Taste oder Leertaste).
<p id="meldung" aria-live="polite"></p>

const meldung = document.querySelector("#meldung");
meldung.textContent = "Bitte gib eine E-Mail-Adresse ein.";  // wird vorgelesen
Tipp: Echte <button>-Elemente reagieren automatisch auf Klick, Enter und Leertaste – ein <div> nicht.
