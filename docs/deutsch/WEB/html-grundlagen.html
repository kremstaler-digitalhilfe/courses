Was ist HTML?

1Die Abkürzung

HyperText Markup Language

  • Auf Deutsch: Hypertext-Auszeichnungssprache

2Keine Programmiersprache!

Sondern eine Auszeichnungssprache

  • HTML beschreibt Inhalte, es rechnet nicht.

3Das Fundament

Das Grundgerüst jeder Website

  • Jede Website baut auf HTML auf.

4Seine Aufgabe

Dem Browser etwas mitteilen

  • Welche Inhalte sind auf der Seite?
  • Welche Bedeutung haben sie? (Überschrift, Text, Bild, Link)

1. HTML-Vokabular

1Tag

Ein Befehl in spitzen Klammern

  • Sagt dem Browser, was dargestellt werden soll.
  • Meist Start-Tag <p> und End-Tag mit Schrägstrich </p>

2Element

Ein kompletter Baustein

  • Start-Tag + Inhalt + End-Tag
  • <p>Das ist ein Text.</p>

3Attribut

Eine Zusatzangabe im Start-Tag

  • Liefert Details, z. B. die Webadresse eines Links oder den Namen eines Bildes.

4Semantik

Die Bedeutung eines Tags

  • <button> = „Hier ist ein klickbarer Knopf“
  • <div> = neutraler Container, keine feste Bedeutung

1Überschriften

<h1> bis <h6>

  • Gliedern den Text hierarchisch.
  • <h1> = Hauptüberschrift (höchste Ebene)
  • <h6> = kleinste Unterüberschrift
  • <h1>Willkommen auf meiner Seite</h1>

2Absätze

<p>

  • Definieren normale Textblöcke.
  • Der Browser fügt vor und nach einem Absatz automatisch Abstand ein.
  • <p>Das ist ein einfacher Textabschnitt.</p>

3Links

<a>

  • Verknüpfen mit anderen Webseiten.
  • Das Attribut href bestimmt das Ziel.
  • <a href="https://example.com">Hier klicken</a>

4Bilder

<img>

  • Bindet Bilder ein – ohne End-Tag!
  • src = Dateiname / Pfad
  • alt = Beschreibung des Bildes
  • <img src="logo.png" alt="Firmenlogo">

5Listen

<ul> <ol> <li>

  • <ul> = ungeordnete Liste (mit Punkten)
  • <ol> = Nummernliste (mit Zahlen)
  • <li> = ein Listeneintrag, immer innerhalb von ul oder ol

6Hervorhebung

<strong> <em>

  • <strong> = fett + als wichtig markiert (wichtig für Screenreader)
  • <em> = kursiv + sprachlich betont
<ul>
  <li>Äpfel</li>
  <li>Birnen</li>
</ul>

Die Grundstruktur

2. HTML-Grundstruktur

Jede HTML-Seite braucht ein festes Grundgerüst, damit der Browser die Inhalte korrekt einliest:

<!DOCTYPE html>
<html lang="de">
  <head>
    <meta charset="UTF-8">
    <title>Mein Seitentitel</title>
  </head>
  <body>
    <header>…</header>
    <main>
      <h1>Hauptüberschrift</h1>
      <p>Inhalt der Seite</p>
    </main>
    <footer>…</footer>
  </body>
</html>

Wichtige Bausteine

1<!DOCTYPE html>

  • Kündigt ein modernes HTML-Dokument an.

2<head>

  • Enthält unsichtbare Metadaten und den Browsertitel.

3<body>

  • Umschließt alle sichtbaren Inhalte.

4Bereiche

<header> <main> <footer>

  • Teilen die Seite logisch auf.
Tipp: Die Bereiche <header>, <main> und <footer> sind wichtig für die Barrierefreiheit – mehr dazu auf der nächsten Seite.

Barrierefreiheit

3. Schlechte Struktur & Screenreader

Blinde oder sehbehinderte Menschen nutzen Screenreader, die Webseiteninhalte vorlesen. Eine unsaubere HTML-Struktur führt zu diesen Problemen:

1Überschriften-Chaos

Ebenen werden durcheinandergebracht oder übersprungen

  • Beispiel: Sprung von <h1> direkt zu <h4>
  • Nutzer verlieren die Orientierung.
  • Screenreader-Nutzer springen gezielt von Überschrift zu Überschrift.

2Fehlende Bereiche

Die „<div>-Wüste“

  • Seite besteht nur aus neutralen <div> statt aus <header>, <main> …
  • Der Screenreader weiß nicht, wo die Navigation aufhört und der Text beginnt.

3Fehlende Bildbeschreibungen

Das alt-Attribut fehlt

  • Der Screenreader liest oft nur den kryptischen Dateinamen vor.
  • Statt zu sagen, was auf dem Bild zu sehen ist.

4Falsche Reihenfolge

CSS verschiebt Inhalte

  • Inhalte stehen im Code an einer anderen Stelle als auf dem Bildschirm.
  • Der Vorlesefokus springt völlig unlogisch hin und her.
Merke dir: Gute Struktur = gute Barrierefreiheit
  • Überschriften der Reihe nach verwenden
  • Echte Bereiche statt nur <div>
  • Jedes Bild bekommt ein alt-Attribut
  • Die Reihenfolge im Code entspricht der Reihenfolge auf der Seite

Manuelles Testen

4. Barrierefreiheit prüfen

Automatische Prüfprogramme finden längst nicht jeden Fehler. Deshalb wird manuell getestet:

1Tastatur-Test

Maus weglegen!

  • Nur mit Tab (vorwärts) und Shift + Tab (rückwärts) bedienen.
  • ZielAlle Links und Knöpfe sind erreichbar.
  • ZielImmer ist ein klarer Fokus-Rahmen sichtbar.

2Screenreader einschalten

Kostenlose Programme

  • NVDA (Windows) oder VoiceOver (Mac) starten.
  • Mit geschlossenen Augen prüfen: Finde ich mich allein über die Sprachausgabe auf der Seite zurecht?

3Erweiterungen nutzen

Browser-Tools

  • Zum Beispiel WAVE, Axe oder eine IBM-Erweiterung.
  • Zeigen direkt auf der Website an, ob Kontraste stimmen oder Beschriftungen fehlen.

Zusammenfassung

HTML = Auszeichnung, keine Programmierung Tag → Element → Attribut Struktur = Bedeutung Immer manuell testen
Merke dir: Gutes HTML …
  • gibt jedem Inhalt die richtige Bedeutung (Semantik)
  • hat ein sauberes Grundgerüst (DOCTYPE, head, body)
  • ist mit Tastatur und Screenreader nutzbar
